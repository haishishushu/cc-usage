## 1. 已明确的核心需求

- **架构方案（已确认）**：统一主面板，按平台能力显示内容；各平台复用页面和组件，由能力配置决定可用指标与状态。
- **产品**：可安装的 Windows 桌面 AI 用量监控工具，常驻运行，追求极低内存占用。
- **平台**：首期 Claude、Codex；平台数量可扩展，预留 Gemini、Grok 等。
- **接入类型**：官方账号、API Key，具体支持方式按平台验证；本地会话记录是独立数据来源。
- **Auth 套餐文案（已确认）**：通过官方订阅 Auth 接入时，主面板显示「当前平台：Claude　当前连接：官方订阅（20x）」这样的套餐信息；格式为「官方订阅（实际套餐名称或档位）」，平台名与套餐随当前账号变化。`20x` 仅为用户提供的展示示例，不是固定值。多个订阅账号通过独立账号名称区分。
- **套餐数据规则**：显示账号接口或可信账号元数据实际返回的套餐名称、等级或倍率；不能根据额度百分比推断套餐。加载时显示「官方订阅（读取中）」；无法获取时显示「官方订阅（套餐未知）」。套餐名过长时单行省略，悬停或键盘聚焦查看完整信息。切换账号同步更新套餐，不能残留上一账号的档位；其他套餐详情仅在真实可获取时展示。
- **核心数据**：可获取的账号额度、API 用量、实时请求 Token；本地统计须注明采集范围，不默认代表整台电脑的全部请求。
- **统计周期**：今日、本周、本月、累计 Token 用量。
- **自定义时间查询**：支持选择开始、结束日期与时间，按指定时间范围查询当前平台的 Token 趋势数据。
- **趋势分析**：主面板必须包含 Token 趋势图和统计周期切换，随所选周期更新趋势数据。
- **请求日志**：位于 Token 趋势图下方，七列依次为时间、计费模型、输入、输出、总成本、用时/首字、状态。
- **核心形态**：灵动岛式悬浮窗，配合完整主面板。
- **灵动岛入口（已确认）**：Auth/API 收缩态不显示「打开主面板」按钮；双击灵动岛进入展开态，展开态右上角才显示「打开主面板」入口，与标题同一行。这是**灵动岛内部唯一**的入口——岛上不再新增任何按钮；系统托盘菜单另有「打开主界面」，两者指向同一个总览页，不冲突。
- **灵动岛显示平台**：在主面板内单选已接入的平台及其连接，同一时刻只显示该配置的数据。
- **灵动岛统计来源（已确认）**：独立保存平台、连接及 Token 统计来源，不跟随主面板浏览切换。多来源时由用户单选，唯一来源自动采用并显示名称；无可用来源时明确提示。
- **Token 增量动效（已确认）**：灵动岛右侧预留固定空间，AI 对话产生可采集的新 Token 消耗时显示「+10k Token」等增量提示，带轻量数字过渡与淡入淡出。Auth/API 共用此交互，增量属于灵动岛当前配置的统计范围。
- **多会话展示（已确认）**：当前统计范围内多个 AI 会话并行时，收缩态合并显示增量，双击展开后按会话展示明细。运行数量和会话名称仅在来源可识别时显示；保留单平台、独立统计来源及既有 Auth/API 布局。
- **主面板查看平台**：右上角图标单选，平台较多时提供「更多平台」。
- **收缩态必显信息（2026-09-15 修订）**：Claude/Codex 官方账号支持 5h、7d 时，两行显示周期、进度和已用百分比；重置倒计时仅在双击展开后显示，整段单行排列。扩展平台按实际能力显示，不虚构 5h/7d，详见第 7 节。
- **API 模式（已确认）**：灵动岛显示平台名、API 标识、今日 Token 和今日费用；双击展开后，通过右上角「打开主面板」进入当前 API 连接总览，查看可查询的剩余余额。
- **只读与可靠性原则（已确认）**：用户自行授权或提供凭证，软件以只读查询和本地采集为主；优先保证额度与 Token 统计可靠，请求日志能查多少就准确展示多少。首期不为补齐日志引入模型请求代理。
- **视觉方向（已确认）**：整体 UI 与 Codex 的视觉风格和主题保持一致，完整支持浅色与深色；覆盖灵动岛、主面板、设置、表格、弹窗和动态状态，具体标准见 4.1。
- **当前用途**：先通过 Pencil 确定 UI，再进入实现。
- **技术栈与性能方向（已确认）**：采用 **Tauri 2 + Rust + React 19 + TypeScript + Vite + Tailwind CSS 4 + shadcn/ui + SQLite**。版本按此钉住，其中 Tailwind CSS 必须是 4.x（与 3.x 是两套配置方式，不可混用），React 必须是 19.x。以低常驻占用为目标，按需创建主面板、共用后台采集、增量处理数据；具体实现约束与性能验收见 7.7，不承诺未经实测的内存数值。

## 2. 先画什么

优先绘制「灵动岛收缩态 → 展开态 → 主面板」这一组核心界面，两套主题保持相同的信息结构。下列布局是对原对话方案的整理；尚未定稿的交互已标注。

- 收缩态只显示所配置的平台及连接。图中的 Claude/Codex 官方账号双额度布局保留；其他连接按实际能力展示，详见第 7 节。切换配置时名称与数据一起更新。
- **按最新布局确认排列每行**：收缩态为周期标签 → 进度条 → 百分比；双击展开后增加独立的剩余时间列，例如 `还剩 3d 5h`，禁止拆成多行。两行各列对齐，标签使用 `5h` 和 `7d`；5h 标签为淡紫底紫字，7d 标签为淡绿底绿字；进度条为绿色填充、浅灰轨道、圆角，百分比为深灰文字，倒计时为较浅灰文字。深色主题沿用相同结构并适配可读性。
- 时间直接显示 `4h 51m`、`3d 7h` 这类紧凑时长，不显示日期、具体时刻或重复的「重置」前缀。本文线框仅表达结构，实际进度条长度按百分比精确绘制。
- 灵动岛显示平台在主面板内单选；多连接时指定其中一个连接，不平均或累加账号额度百分比。灵动岛不增加独立的平台设置入口。
- Auth/API 收缩态只显示信息，双击灵动岛进入展开态；悬停仅提供视觉反馈或信息提示，不自动展开。展开态右上角显示「打开主面板」，单击按钮才进入总览。按钮单击不触发拖动或收缩；灵动岛不增加独立的设置或详情入口。
- 对支持 5h/7d 的连接，收缩态显示两项额度，倒计时需双击展开后查看；此类连接收缩态是否额外显示今日 Token 待确认。没有额度能力时采用第 7 节替代布局。
- 展开态也只展示所配置连接的可用额度及今日 Token，并标注来源。
- 原对话建议支持：置顶、拖动、位置设置、大小调整、透明度、隐藏、系统托盘；具体默认值待确认。

#### 2.1.3 拖动与贴边停靠（已确认）

灵动岛可拖动到屏幕上、下、左、右任一边缘吸附，吸附后收成一条极窄的「停靠条」。

- **形态层级**：停靠态与收缩/展开是两个维度。停靠 = 位置贴边 + 尺寸收到极小；收缩/展开 = 信息量多少。停靠态比收缩态更收一级。
- **手势**：桌面端按住即可拖动，**不使用长按**——长按是触屏手势，且会与既有的「双击展开、单击不展开」挤在一起。拖动期间暂停 Token 增量提示的位移动画。
- **吸附提示**：指针距边缘 ≤ 24px 时，该边缘出现 3px 强调色指示条与半透明吸附区；松手后约 180ms 内收成停靠条并对齐边缘。
- **停靠条尺寸**：上/下边缘为 120 × 14 的横条，左/右边缘为 14 × 120 的竖条。贴屏幕那一侧为直角，露出侧为 7px 圆角。
- **停靠条内容**：只保留两条水位条（5h / 7d），轨道 3px、间距 2px、沿边内边距 8px。**不显示平台名、百分比、倒计时与 Token 增量文字**。上/下横条水位自左向右生长，左/右竖条自下而上生长。着色沿用第 3 节的水位阈值（< 75% 绿 / 75–89% 琥珀 / ≥ 90% 红）。
- **悬停探出 Peek**：停靠态下悬停约 150ms 滑出完整收缩态，指针移开 500ms 后自动缩回。需要具体数值时探出即可，无需先解除停靠。
- **双击语义**：对停靠条双击 = 解除停靠、回到自由态收缩态；在探出状态下双击才进入展开态。若展开期间没有拖动，第二次双击先回到原边缘的完整探出态，指针移开 500ms 后自动缩回停靠条；只有实际拖动才解除原停靠关系。不破坏「双击 = 展开」的心智。
- **屏幕约束**：吸附按当前显示器的工作区计算，不跨显示器、不覆盖 Windows 任务栏。多显示器下记录「显示器 + 边缘 + 沿边偏移」，显示器变更后回落到最近的有效边缘。
- **增量提示**：停靠态不显示增量数字，改为水位条一次约 300ms 的轻微亮度脉冲；无新增事件时不播放，遵循减少动态效果偏好时直接跳过该脉冲。
- **不可用状态**：未连接、查询失败、来源不可用时停靠条只保留空轨道，不着色也不画成满格，与「真实已用 100%」区分。
- **无套餐状态（API Key，2026-09-19 确认）**：无套餐的 API Key 停靠条画**两条满格蓝色轨道**（`$accent-blue`），表示「不设套餐上限、按量计费」，与 API 徽标的蓝色身份一致。判定口径同「套餐」定义（5h / 7d 窗口）：查询有结论却查不到这两个窗口即按无套餐画蓝——**包括网关只返回总配额、月消费等非套餐窗口的情况**（这些窗口的真实数据仍在岛卡片与主面板展示）。查询失败、限流、凭证失效仍画空轨道，与「失败空轨道」「真实耗尽红满格」三者可区分。
- **持久化**：停靠位置、所在边缘与沿边偏移需持久化，重启后恢复到上次停靠状态。相关开关归入设置「悬浮窗附加选项」，不新增一级设置页。
- 输入、输出和缓存明细可作为展开态的扩展内容，是否保留待确认。

#### 2.1.1 右侧 Token 增量区与动画

- 收缩态采用「左侧常规数据 + 右侧增量提示」布局；右侧参考宽度 112px，与左侧间距 16px。空闲时保留空间但不显示数字，新增消耗时显示 `+10k Token`、`+2.4k Token` 等；线框中的「右侧固定预留区」仅为设计注释，实际界面不显示。
- 右侧增量是短时间内新增的已采集 Token，不是今日累计值、每秒速率或额度变化。不到 1000 时显示整数，较大值用 k/M 紧凑表示；显示取整不改变底层统计精度。
- Auth/API 均保留右侧增量区；展开态也保留此区，在标题行下方，不挤占右上角「打开主面板」。提示出现或消失不改变窗口宽度、不推动左侧数据、不覆盖按钮。
- **动画方案（已修订）**：首次出现以约 200ms 淡入并轻微上移 4px；此后**数值就地累加**，数字以 ease-out 在约 900ms 内追到最新已采集值，连续事件从当前进度继续追数，不反复缩放。参考 Claude Code 计数连续性的交互表现，不宣称复用其内部算法。合计和会话明细共用帧循环，收缩/展开不重播；使用等宽数字避免横向抖动。
- **常驻规则（已修订）**：只要该会话仍在进行，增量数字就**保持显示且不自行消失**——暂时没有新增时数值固定不动，有新增时立刻补间累加。**会话全部结束后**才用约 300ms 淡出并归零，下一轮会话从新的增量重新开始。原先「最后一次更新后停留 1.5 秒即淡出」的规则作废：会话还在跑却把数字收走，会让人误以为消耗停止了。
- 高频事件在下一动画帧更新显示目标，不使用持续推迟的防抖定时器；不叠加多条漂浮文字。只对日志已提供的真实用量插值，不预估尚未收到的 Token。归零只作用于展示层，日累计始终由统计层维护，动画不能再次计入 Token。
- 只展示当前平台、连接和选中来源实际采集到的新增事件。来源提供流式用量时随采集更新；只在请求结束提供用量时，在结束后提示，并在来源说明中标注「请求结束后更新」。不按打字速度或动画帧伪造消耗。
- 首次加载、历史导入、启动补采、切换平台/连接/来源、跨日归零和统计校正不触发增量动画；切换配置立即清理旧提示。同一请求若返回累计 Token，先按请求标识和已采集值求增量、去重，不能重复展示整段累计值。
- 只有历史汇总、无法区分实时增量的来源不播放实时提示；保持预留区空白，主面板/设置的来源说明标注不支持实时增量。来源暂时中断时不继续模拟增长。
- 增量提示不增加点击动作，仍遵守「双击灵动岛展开，单击不展开」。数值稳定后补间自行结束、不再占用帧循环；遵循减少动态效果偏好时，以直接更新替代补间与位移。
- Pencil 必须提供空闲、首次新增、连续增长、停留、淡出、切换清空的状态帧，并标注时长；静态画板不能只放一个永久显示的 `+10k Token`。

#### 2.1.2 多会话并行与增量汇总

- **收缩态**：当前平台、连接和所选来源内多个会话共用右侧增量区，显示当前提示段内新增 Token 的合计；有可信运行状态时，在右侧上方显示「3 个会话运行中」。无运行会话时不显示数量，保留空白和原有数据区。
- **展开态**：保留右上角「打开主面板」、原有额度或 API 今日统计、来源及更新时间；在数据区下方增加会话列表，每行显示状态、名称和当前提示段内的新增 Token。图中名称、状态及数值均为样例，需来源实际提供。
- 两种状态共用第 2.1.1 节的合并时间段与动画规则；示例 `8.0k + 3.2k + 1.2k = 12.4k`。会话行增量与右侧合计是同一批事件的不同展示，不能再次累加到今日统计。右侧合计包含当前范围内未展开显示的会话。
- 同账号的会话共享账号额度，5h/7d 仍只展示一份，不求和、不取平均；其他平台、连接或统计来源的会话不混入。来源无法按账号区分时，沿用已有覆盖范围说明，不能声称是该账号的专属会话。
- 展开列表最多显示 3 条；超过时显示非按钮文案「还有 N 个会话」，N 为当前列表范围中未显示的数量。保留唯一的打开主面板入口，不新增会话详情页或操作按钮。
- 会话按首次出现时间降序排列，最新的会话在最前面（2026-09-19 鼠鼠定版，替代早期“顺序保持稳定、新会话追加”的口径）；首次时间取该会话请求的最早时间戳，Token 更新不改变排序，列表不随增量刷新反复重排。顺序变化（如新会话出现）以约 200ms 位移过渡平滑换位，不做瞬时跳动，系统开启减少动态效果时直接落位。标题过长时省略，悬停或键盘聚焦查看全名；会话必须显示来源中的真实标题，缺失时显示“未命名会话”，不展示 ID、不生成猜测的任务名称。
- 有可信完成事件时，该行短暂显示「已完成」，约 1.5 秒后退出运行列表；运行数量立即扣除已完成会话。失败显示失败状态；来源中断时标明状态未知，不仅凭一段时间没有 Token 就认定完成。
- 只有来源提供稳定会话标识、且运行状态可由来源直接给出或由写入新鲜度可靠推定时，才显示「运行中」数量；两者都做不到时使用「最近活跃会话」，不得称为运行中。近期窗口按来源刷新能力定义，并把判定口径写进来源说明。
- **本地会话记录的实测结论（已实现）**：Claude Code 与 Codex 的 jsonl 提供稳定会话标识。Codex 运行状态读取 `task_started`、`task_complete`、`turn_aborted` 与 `final_answer` 生命周期事件；收到结束事件立即退出运行列表。`compacted` 与 `context_compacted` 表示任务内自动压缩上下文，不是结束事件，压缩期间必须保持运行；不得用日志静默时长推断任务结束。没有可信生命周期的来源只显示“最近活跃”，当前窗口为 90 秒，不得称为运行中。会话标题取 Claude Code 的 `ai-title` 行与 Codex `session_index.jsonl` 中按 `id` 关联的 `thread_name`；改名后同步更新，缺失时显示“未命名会话”。ID 仅用于内部关联，不在列表中代替标题。
- 无法区分会话但能获取可信增量时，仅保留合并增量，不虚构会话数量或列表；历史汇总不触发多会话实时动效。一个会话的多个请求不算多个会话，跨来源相同记录不能重复计数。
- 收缩态只对合计数字做平滑更新；展开态更新对应行时短暂轻微高亮，不同时播放多条漂浮动画。已完成记录移出不缩减此前已确认的增量；每段提示结束后的清零只作用于展示，不修改累计 Token。
- 现有七列请求日志继续展示请求级记录，不因增加会话列表而新增第八列；会话可能包含多次请求，会话数不等于请求数。
- Auth 与 API 都使用上述规则；单会话仍保留原有右侧增量体验。所有会话区均保持双击展开规则，单击会话行不新增动作。

| 列 | 展示要求 |
|---|---|

| 输入 | 右对齐，使用千位分隔及等宽数字，保留精确 Token 数 |
| 输出 | 与输入列同宽、右对齐，采用相同数字格式 |
| 总成本 | 右对齐、适度加粗；同币种金额统一显示精度，示例为四位小数。非零微小金额不可显示成零，可显示 `<$0.0001`；实际币种和成本口径待确认 |
| 用时/首字 | 左对齐、两行显示：第一行总耗时如 `2.1s`，第二行次级文字 `首字 0.3s`；缺少某项时该项显示 `—`，不伪造为 `0.0s` |
| 状态 | 居中，用小图标和实际响应码/状态组成轻量标签；成功为绿色 `✓ 200`，限流为琥珀色 `! 429`，失败为红色，未知为中性色 `—`。不只依赖颜色区分 |

- **Pencil 绘制参数（本次优化采用的设计方案）**：表格圆角 14px、外边框 1px、表头高 44px、数据行高约 64px，单元格水平内边距 16px；正文 13px、次级信息 12px、区块标题 16px。文字较长或缩放时允许行高增加，避免裁切。
- 表头使用浅灰底和中等字重，表体保持纯净背景，只用细横线分行，不画竖线、不叠加厚重阴影。行悬停显示轻微背景色；数据行不呈现按钮式手型，未增加点击详情功能。
- 基准表格宽度 1064px，列宽按「时间 128 / 计费模型 244 / 输入 108 / 输出 108 / 总成本 128 / 用时首字 144 / 状态 104」分配（含单元格内边距）；宽屏新增空间优先给模型列，窄窗口表格内横向滚动，不隐藏列。表头与数据同向对齐。
- 所有数字使用等宽数字，避免刷新时抖动；金额仅适度强调，不让每列都加粗。次级信息仍需保持可读对比度，深色模式使用对应主题色。
- 表格与趋势图区块间距约 24px；区块标题为「请求日志」，紧邻显示当前平台名称。复用已有时间筛选，不再增加一套日期工具栏。
- 仅保留用户指定的七列；截图中的「供应商」「来源」不加入表格，输入下方的缓存 R/W 明细也不自动新增。
- 日志复用上方统计周期和自定义时间范围筛选；切换平台、周期或确认自定义范围后，趋势图和日志同步更新。该联动为本次整理采用的默认方案。
- 未获取到的输入、输出、成本、耗时等显示 `—`；若成本为估算值，必须标识「估算」，不能当作实际账单金额。
- 默认按时间从新到旧排列；分页默认每页 10 条。「每页 N 条」这句文案不在界面上显示，也不提供页大小切换控件。
- **分页条结构（已确认）**：左侧显示当前筛选范围内的总条数，格式为「共 161 条记录」；右侧依次为上一页箭头、页码按钮组、下一页箭头，再接页码输入框与「跳转」按钮。

```text
共 161 条记录                      ‹  1  2  3  4  5  …  17  ›   [ 页码 ] [ 跳转 ]
```

- **页码省略规则**：页码按钮最多占 7 个位置，超出时用「…」省略，「…」不可点击。
  - 总页数不超过 7：全部列出，不出现「…」。
  - 当前页靠前（c ≤ 4）：`1 2 3 4 5 … N`
  - 当前页靠后（c ≥ N-3）：`1 … N-4 N-3 N-2 N-1 N`
  - 当前页居中：`1 … c-1 c c+1 … N`
- 当前页为实心强调色按钮、白色数字；其余为描边按钮。首页禁用上一页箭头，末页禁用下一页箭头，禁用态降低不透明度而非隐藏。
- 「跳转」校验输入为 1 到总页数之间的整数，越界或非法输入不提交，就近提示；页码输入框为占位文案「页码」，不预填当前页。
- **总条数依赖来源能提供可靠计数**：无法取得总数时显示「共 — 条记录」并降级为上一页/下一页按钮，不显示页码按钮，也不推算页数。这一点优先于本节其余分页描述。
- 筛选变化回到第一页，普通刷新保持当前页与浏览位置。
- 首次加载使用与表格列宽一致的骨架行；空状态在表体中显示「当前时间范围内暂无请求」，保留表头；查询失败在表体显示失败提示，不伪装为空数据。刷新时维持列宽和当前滚动位置。
- 所有行内容均为设计示例。

  - 绿色使用可读性更高的文字绿（浅色 `#06834A` / 深色 `#3ADB8B`），不使用额度进度条的 `#06C167`，以保证 32px 大号数字在白底上的对比度。

- 今日费用优先使用对应连接、来源和统计时区下的服务商费用数据；模型和 Token 数据足够时可估算，并将标签改为「今日费用（估算）」。无法获取或可靠估算时显示 `—`，不为了填值发起模型调用。
- 余额不可由「充值金额减本地估算消耗」自行推算；费用与余额分别记录来源、币种、查询范围和更新时间。不能从组织总费用推断当前 Key 的今日费用。
- 普通调用 Key、管理凭证和余额查询权限是不同能力；如需额外查询凭证，在设置中明确说明用途和权限，不默认已有 Key 能访问账单。具体服务商适配仍需验证。

## 3. 数据表达规则

| 数据类型 | 界面重点 | 不能混淆的内容 |
|---|---|---|
| 官方账号额度 | 平台、账号、实际窗口（首期以 5h/7d 为例）、可用的已用/剩余值及重置倒计时 | 额度百分比不能直接换算成本地 Token 数量；不支持的字段不推测 |
| API 用量 | 平台、账号或 Key 标识、统计周期、Token 用量 | 不默认套用官方订阅的 5h/周额度卡片；可用字段待接入确认 |
| 本地 Token | 本地来源、今日/本周/本月/累计消耗 | 不默认与服务端 API 数据相加，以免同一消耗重复统计 |

- 百分比统一表示「已用」，进度条与其含义一致。收缩态按参考图片仅显示数值（如 `10%`），不重复添加「已用」文字；完整说明或悬停提示可明确其含义。
- **额度水位着色（已确认）**：进度条填充色按「已用百分比」取色，对 5h、7d 及其他所有额度窗口使用同一套阈值，不因窗口长短改变。

| 已用百分比 | 进度条颜色 | 等级 |
|---|---|---|
| < 75% | 绿 `$success` | 正常 |
| 75% – 89% | 琥珀 `$warn` | 接近上限 |
| ≥ 90% | 红 `$danger` | 即将耗尽 / 已耗尽（100%） |

  - 阈值取 75% 与 90% 的理由：75% 是「还剩四分之一」的自然分界，90% 是「一两次长会话就会用完」的临界点；两档之间保留 15 个百分点缓冲，避免告警一闪而过导致用户对颜色脱敏。
  - 着色只作用于进度条填充。轨道颜色、周期标签（5h 淡紫底紫字 / 7d 淡绿底绿字）与百分比文字颜色都不随水位变化——标签表示窗口身份，不表示水位。
  - 颜色是冗余编码而非唯一通道：进度条长度与已用百分比数字始终可读。灵动岛收缩态不显示等级文字，主面板的宽额度行另给「正常 / 接近上限 / 已耗尽」等级标签。
  - 查询失败、未连接、接口不支持时不着色也不画进度条，与「真实已用 100%」分开表达，不能把失败画成满格红条。倒计时到零显示「等待更新」，不把已用额度清零。
  - 例外（2026-09-19 确认）：无套餐的 API Key 停靠条画满格**蓝色**（非水位三色），表达「不设套餐上限」；蓝色满格不进入水位阈值表，与红色满格（已耗尽）语义不同。
  - 后续可选的细化方向（待确认，首期不做）：结合窗口剩余时间的消耗速率判定，例如 5h 窗口在即将重置时适当放宽告警。首期采用纯百分比阈值，保证可预测、不误报。
- 无数据、未连接、接口不支持、真实零用量必须可区分；不可把查询失败画成 0%。
- 本文所有额度区域的「重置时间」均指距该窗口重置的剩余时长，显示倒计时而非绝对日期时间。5h 与周额度分别关联各自倒计时，避免使用一个含义不明的 Reset 字段。
- 数值使用 K/M/B 等紧凑格式，保留 Token 单位或所属统计标题。
- API Key 只显示脱敏标识。
- **接入类型徽标（已确认）**：平台名旁用小徽标标明当前连接的接入类型——官方订阅显示绿色 `Auth`，API Key 显示蓝色 `API`，本地采集显示中性色 `Local`。徽标只表示接入类型，不表示套餐、额度或连接状态；具体套餐名仍由旁边的文字承载，并遵守上文的套餐数据规则。连接状态另用 StatusBadge 表达，不与接入类型徽标合并。
- **文本溢出（已确认）**：宽度不足的文本单行截断并以「…」结尾，不换行、不缩小字号；完整内容通过悬停或键盘聚焦提示查看，不新增页面入口或常驻按钮。适用于会话名称、计费模型、套餐名、连接名称与来源名称。数值与金额不省略，始终用等宽数字加 K/M/B 紧凑单位完整显示，宽度不足时加宽列或横向滚动。
- 原对话建议的输入、输出、缓存读取、缓存写入、请求数、平均每次请求 Token：按数据源实际支持展示，统计口径待确认。
- 请求日志「总成本」列与 API 灵动岛「今日费用」均已确认，必须设计；缺失值和估算标识按 2.4/2.5 展示。除这两项外的其他费用汇总仍为可选建议，模型与金额示例不是已验证事实。

- 扩展页面启用后复用：`AccountCard`、按钮、Tabs、设置表单控件，以及主面板已有的趋势图和周期切换组件。

### 6.2.1 接入方式的判定（已实现）

接入方式**只有官方订阅（`Auth`，绿）与 API Key（`API`，蓝）两种**，不存在第三种标签；数据来源（本地会话记录等）不是接入方式，不得占用该标签位。

本机配置按以下顺序探测，只检查环境变量与配置文件中**键是否存在且非空**，绝不读取、传输或存储凭证值：

| 平台 | 判定为 `API` | 判定为 `Auth` |
| --- | --- | --- |
| Claude | 环境变量 `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN`；或 `~/.claude/settings.json` 的 `env` 内同名键、`apiKeyHelper` | `~/.claude/.credentials.json` 存在 `claudeAiOauth` |
| Codex | 环境变量 `OPENAI_API_KEY`；或 `~/.codex/auth.json` 的 `OPENAI_API_KEY` 非空 | `~/.codex/auth.json` 存在 `tokens` |

两者同时存在时以 API Key 为准（与 CLI 自身的优先级一致）。都探测不到时不显示任何接入方式标签，不臆测。

### 6.3 添加与移除连接（已确认）

**连接只有两种类型**：官方订阅（Auth）与 API Key。**本地会话记录不是连接**——它是「统计来源」，由后台自动发现，出现在统计来源选择器里，**不出现在连接表与添加流程中**。

**两个入口，职责不同**

| 入口 | 位置 | 作用 |
|---|---|---|
| **获取** | 连接表**每一行内**，排在「重新授权」/「更换 Key」前面 | 重新读取本机 Claude / Codex 已有的授权凭证与 API Key，刷新**已存在**连接的凭证。不新建连接、不改变连接名称与类型 |
| **+ 添加连接** | 连接管理区块标题右侧 | 建立**新**连接。空状态时表体中央另给「添加第一个连接」 |

- 「获取」读的是**凭证**（授权 token、API Key），用于查额度与余额；「本地会话记录」读的是**会话日志**，用于统计 Token。两者都读本机，但读的文件与用途完全不同，不可混为一谈。
- 连接已过期时「获取」排在「重新授权」前面：用户若刚在 CLI 里重新登录过，直接重读本地凭证即可，无需再走一遍浏览器授权。
- 凭证读取范围需在界面上说明（扫描了哪些路径与环境变量），不静默读取用户未预期的位置。

**「获取」的四种状态**

| 状态 | 表现 |
|---|---|
| 默认 | 蓝色描边按钮「获取」 |
| 获取中 | 按钮禁用并显示「获取中…」，避免重复触发 |
| 成功 | 绿色「已更新凭证」，行状态刷新为「已连接」、最近同步置为「刚刚」，约 1.5 秒后回到默认态 |
| 未找到 / 失败 | 琥珀色「未找到本机凭证」，提示改用「重新授权」或「+ 手动添加」。**不得清空或破坏现有连接**，保留原状态并就近提示 |

**为什么保留「+ 添加连接」**：「获取」覆盖不到四种情况——本机没装 CLI、想加第二个账号（CLI 只存当前登录的那一个）、Key 不在本机（密码管理器 / 公司下发）、凭证加密或权限不足导致读取失败。删掉手动添加，这四类用户将无法使用本软件且无补救手段。故「获取」为主路径，「+ 手动添加」为兜底。

**添加流程（两步 + 一个分支）**

| 步骤 | 内容 |
|---|---|
| 第 1 步 选择平台 | 平台列表由配置生成。已实现但未连接的平台可选中；未接入的平台禁用并标「待接入」，与「尚未连接」区分 |
| 第 2 步 选择接入方式 | 官方订阅（绿色 `Auth` 徽标）：浏览器授权，可读 5h / 7d 额度、重置倒计时与套餐；API Key（蓝色 `API` 徽标）：可查今日 Token 与费用，余额是否可查取决于服务商接口。**提前说明两者能读到的指标不同**，避免接完才发现没有额度数据 |
| 分支 A · 官方订阅 | 在默认浏览器打开授权页，弹窗内显示等待态与「重新打开授权页」。软件不接触账号密码，只保存授权返回的凭证 |
| 分支 B · API Key | 填写连接名称 + 粘贴 Key。Key 仅保存在本机，界面与日志始终只显示脱敏标识 |

- 同一平台下两种接入方式可以并存，也可以有多个 API Key；连接名称由用户填写，用于在灵动岛与主面板中区分。
- 验证失败、授权被拒绝或超时时停留在当前步骤并就近提示，**不关闭弹窗、不留下半成品连接**。
- 授权流程按各平台实际支持方式适配，稿中的「浏览器授权」为通用示意，具体能力待接入前验证。

**移除连接（破坏性操作，必须二次确认）**

- **移除只断开连接**：删除凭证与配置，**历史统计数据保留**。要删数据走「数据 → 历史清理」，避免一个按钮承担两种不可撤销后果。重新添加同一账号时历史能接上。
- 被移除的连接如果**正是灵动岛当前配置**，确认框必须提前给出橙色警示：移除后灵动岛将没有可显示的连接，需要在「设置 → 灵动岛」中重新选择，**不会自动换成其他账号**（与 7.3 一致）。该警示块只在这种情况下出现。

**空状态（一个连接都没有时）**

| 位置 | 表现 |
|---|---|
| 连接管理表 | 保留表头，表体居中显示「还没有任何连接」+「添加第一个连接」主按钮 |
| 灵动岛 | 显示「尚未添加连接 · 双击展开后打开主面板添加」。不画进度条、不显示 0%，托盘角标为中性灰 |
| 主面板总览 | 引导卡替代额度卡，说明两种接入方式各能读到什么，并给「添加连接」按钮；**不显示一堆 `—`** |

## 7. 多平台扩展设计与审查结论

本节的「统一主面板，按平台能力显示内容」架构已获确认，作为后续设计依据。具体平台能力、授权方式和刷新限制仍需在接入前验证；文中单独标注待确认的细节保持待确认。

### 7.1 方案与修订依据

已确认采用「统一主面板，按平台能力显示内容」，通过「统一页面 + 平台能力配置 + 独立数据适配」实现扩展。新增平台补名称、图标、连接方式和数据适配，复用主面板、七列日志及灵动岛。

| 方案 | 取舍 |
|---|---|
| 统一页面、按能力显示（采用） | 复用布局，允许各平台数据不同，首期工作量可控 |
| 每个平台独立做页面 | 自由度高，但容易重复维护、样式和交互不一致 |
| 用户自由搭建仪表盘 | 灵活，但会引入配置编辑器和大量状态，不适合当前简洁目标 |

| 审查发现 | 修订方案 |
|---|---|
| 平台选择、组件状态写死为两个 | 平台列表生成界面，增加溢出菜单 |
| 强制所有平台显示 5h/7d | 按真实额度窗口展示，无额度时显示 Token 或明确说明 |
| 多账号无法确定额度属于谁 | 平台下选择具体连接，灵动岛另存自己的配置 |
| API、本地会话、实时请求可能重复 | 选择明确的数据来源，无法可靠去重时不合并 |
| 日志暗示必有成本/首字/HTTP 状态 | 七列允许缺失；不支持逐条日志时显示能力说明 |
| 平台切换和时间筛选缺少一致性规则 | 统一查询范围，旧响应不得覆盖新平台 |
| 表格列宽之和与基准宽度不符 | 基准宽度修正为 1064px，窄窗口表格内滚动 |

### 7.2 区分平台、连接、来源与模型

- **平台**：产品导航对象，首期 Claude、Codex，未来可扩展 Gemini、Grok。使用稳定标识，不能依赖可修改的名称判断。
- **连接**：一个平台下的具体账号、API Key 或本地采集配置。平台可有多个连接；账号/Key 名称可区分，密钥只显示脱敏内容。
- **来源**：额度接口、API 汇总、实时请求、本地会话记录，各自有可获取字段、采集范围与更新时间。
- **模型**：请求中的模型属性。新增模型通常只是新增数据，不新增平台标签；计费模型未知时显示 `—`，不以平台名或猜测模型替代。
- 未来第三方转发连接的平台归属由配置确定，不能仅靠模型名称推断供应商；产品平台与实际计费方分别保存，七列表格不因此增加列。

- 已实现但未配置的平台仍可选中，展示「尚未连接」和设置入口；不能与「尚未实现」混为一谈。
- 当前视图单选一个平台、一个连接；只有一项时显示名称，多项才显示下拉。首期不添加跨账号混合额度视图。
- 有些本地记录可能无法归属到账号；这类来源标注「本平台本机记录，无法按账号区分」，同时说明连接过滤不适用，不能冒充个人账号专属统计。

- 灵动岛独立保存平台、连接及 Token 统计来源；主面板更改平台、连接、来源或时间范围均不回写该配置。打开主面板先定位到灵动岛的平台、连接和统计来源，随后可以独立浏览。

- 切换灵动岛平台或连接时，重新校验来源是否适用；旧来源不适用时清除其选择和旧统计值，单项自动采用，多项提示选择。已选来源暂时失败时保持选择并标明过期或失败，不静默切换到其他来源。
- 灵动岛统计来源决定今日 Token；Auth 额度和 API 余额使用所选连接各自对应的接口。API 今日费用遵循 2.5：优先查询该连接有权限且范围匹配的费用，无实际费用时才可基于已选来源可靠估算；来源或范围不同需在设置预览中说明，不能混作同一口径。
- 来源名称与覆盖范围在设置预览和展开态说明；紧凑态可通过 Token 标签的悬停/聚焦提示查看，不新增页面入口或常驻按钮。无法按账号区分的本地来源需明确提示其范围。
- 灵动岛所选连接失效时保留名称和失效状态，通过唯一的「打开主面板」入口修复。主面板提供配置预览，避免用户看不出哪次操作会改变灵动岛。

### 7.4 平台能力决定展示内容

连接需要声明是否支持：额度窗口、Token 汇总、请求日志、费用查询、余额查询、首字延迟，以及可用来源。费用与余额是独立能力。额度是一组可变窗口，每项包含名称、单位、已用/总量（可缺失）、重置时间（可缺失）和更新时间，而不是固定两个字段。

| 实际能力 | 主面板 | 灵动岛 |
|---|---|---|
| 有 5h 与 7d | 双额度及各自倒计时 | 保留用户确认的双行布局 |
| 有其他窗口 | 显示真实窗口名称与单位 | 最多选两项；完整指标在主面板查看 |
| 只有一个窗口 | 仅展示一项 | 一行额度；有 Token 数据时第二行可显示今日 Token |
| API 连接 | 顶部显示余额或明确的查询不可用状态，统计照常 | 今日 Token + 今日费用，缺失项显示 `—`，详见 2.5 |
| 其他无额度但有 Token 的来源 | 额度区说明「此连接不提供额度信息」，统计照常 | 今日 Token 与最近更新 |
| 无总量分母 | 显示可用的已用数量和单位 | 不生成百分比进度条 |
| 无重置时间 | 说明未提供 | 倒计时位置为 `—`，不推测重置时间 |

| 更新失败但有历史值 | 保留最后值并标明过期与更新时间 | 保留旧值并显示轻量过期标记 |

### 7.5 统计、查询与日志的一致性

- 趋势图与日志共用平台、连接、来源和时间范围；顶部自然周期卡只跟随平台/连接/来源。来源筛选可以随数据能力改变，但必须显示当前来源。
- 数据保存绝对时间，显示与自然周期计算使用设置中的统计时区，初始取系统时区。本周从周一 00:00 起，本月从月初起；累计从现有最早记录起，并展示采集起点，不能称为账号终生消耗。
- 查询区间包含开始、不包含结束；自定义输入精确到分钟。跟随当前时刻时，同一次图表与日志查询使用同一个结束时间快照。
- 今日按小时、周/月按日展示；长时间范围降低图表点数而非加载所有日志，并显示实际分桶粒度。日志保留原始时间精度。
- 平台/连接/来源/时间变化时进入对应加载态；缓存按完整范围区分，旧请求返回不得覆盖新选择的数据。
- API 汇总、本地会话与实时请求不默认相加；有稳定请求标识时去重，没有可靠映射时保留来源边界。会话/批次数据不能当成逐条请求。
- 输入/输出/缓存字段可能存在重叠，总 Token 优先采用来源提供且语义明确的总值，不无条件把缓存再次累加；无法统一的口径要说明。
- 成本保留数值、币种、实际或估算标识，不把不同币种直接相加，不把订阅费伪装成单次请求实际账单。估算须标识并使用适用模型与时间的价格，无法估算时为 `—`。
- 本地日志没有 HTTP 响应码时，可显示其真实「成功」状态，不能自动补 `200`；没有首字延迟或耗时则保留 `—`。
- 额度与统计来源分别显示更新时间；一个来源失败不清空其他成功区块。历史图与日志若来自不同粒度或采集覆盖，明确说明，不能暗示必然逐条对得上。

**Tailwind CSS 4 的具体约束：**

- 配置方式是 CSS-first：主题变量写在 CSS 的 `@theme` 指令里，不再使用 `tailwind.config.js`。v3 的 `@tailwind base / components / utilities` 三条指令已取消，改为单条 import。
- Vite 使用官方的 `@tailwindcss/vite` 插件，不走 PostCSS 插件那条路。`tsconfig.json` 需配置 `baseUrl` 与 `@/*` 路径别名，`vite.config` 需配置对应的 resolve alias，否则 shadcn CLI 无法解析导入。
- **不得从 v3 起步再升级**：升级不彻底时，后续用 CLI 新增的组件仍会按 v3 / React 18 版本安装，导致同一项目里混入两套写法。新项目直接以 v4 初始化。
- shadcn/ui 在 v4 下的既定差异：每个基元带 `data-slot` 属性；默认风格为 new-york；toast 已废弃，改用 sonner；按钮使用默认光标。这些差异不影响第 4 节已确认的视觉规范，但组件改写时按其现状适配，不回退到旧写法。
- npm 安装 shadcn 组件可能触发 peer dependency 冲突，CLI 会提示选择 `--force` 或 `--legacy-peer-deps`；pnpm / bun / yarn 无需额外参数。
- Tailwind v4 面向现代浏览器。本项目仅通过 Windows WebView2（常青版 Chromium）渲染，不存在兼容问题；不需要为旧浏览器降级。

**设计变量落地（第 4 节 → 代码）：**

- 第 4 节已确认的颜色、圆角、间距变量统一落到 CSS 变量，由 `@theme` 声明，浅色/深色通过主题类切换，保持两套主题使用同一组变量名。
- shadcn/ui 在 v4 下的色值采用 OKLCH。设计稿中的 hex 值转换为 OKLCH 后，**必须重新核对对比度**，尤其是专门为可读性挑选的几个值：文字绿 `#06834A` / `#3ADB8B`（额度等级、Auth 徽标、余额充足态）、警告 `#D98500` / `#F0A93B`、错误 `#DC2626` / `#F26D6D`、以及 Codex 与 Grok 平台标识的黑白翻转色。转换不得改变这些值的可读性结论。
- 平台标识与应用图标是矢量路径，不参与主题色变量系统之外的自动换色；其取色规则见 2.2 与 4.2.1。

**窗口与后台生命周期：**

- 灵动岛常驻且只加载摘要和必要会话数据。收缩、双击展开复用灵动岛窗口，不因展开新增一套后台采集；保持第 2 节的唯一主面板入口。
- 主面板按需创建，关闭时释放对应窗口及前端资源，停止图表、表格刷新和视图订阅；不能仅隐藏后继续常驻全部数据。重新打开允许有短暂加载态，配置与必要浏览状态通过轻量状态恢复，再按 7.3 定位灵动岛所选范围，不保留整页历史数据来换取恢复。
- 主面板关闭不退出应用，也不停止必要采集或灵动岛更新。最小化与关闭分开处理；主面板不可见时暂停非必要渲染和刷新，恢复可见后查询最新数据。
- 平台和会话共用 Rust 后台，由适配器管理数据；不为每个平台、账号或会话创建独立 WebView。同一来源的采集任务由多个视图复用，避免每次打开窗口重复采集。

**采集、刷新与内存边界：**

- 本地记录采用增量读取与去重，避免定时全量扫描、反复解析全部历史；SQLite 查询配合实际过滤和排序建立必要索引。
- **实时机制（已实现，不使用轮询）**：Rust 侧用 `notify` 递归监听 `~/.claude/projects` 与 `~/.codex/sessions`。CLI 每收到一次响应就往 jsonl 追加一行，因此**文件写入即用量事件**；写入触发增量采集后，通过 Tauri 事件 `live-usage` 主动推给前端，前端只订阅不请求。单次响应的多次写抖动以 **120ms** 去抖合并为一次采集。另设 **10 秒**心跳兜底，仅用于监听失效（网络盘、权限、句柄耗尽）时恢复，正常路径不产生新增。目录不存在时跳过该平台，不报错。
- 实时 Token 由本机日志事件驱动，通过共享动画帧平滑更新展示，不等待事件停止。官方额度、余额等网络查询使用独立且较低频率的调度，遵守平台限制并在失败时退避；数字动画不触发网络查询。
- Rust 负责统计与请求累计值求差，前端只更新变化区域。事件队列和缓存设置容量上限；显示事件可合并，但不得丢失统计记录或重复累计 Token。
- 请求日志默认每页 10 条，按当前范围分页查询，总条数与当前页数据一并由后台返回；来源无法提供可靠计数时返回总数未知标记，由 UI 降级为上一页/下一页。趋势图在后台按周期聚合并限制返回点数，不向前端发送全部原始日志。切换范围后旧结果不能覆盖新结果。
- 无新增 Token 时停止增量动画，无数据变化时避免重复渲染；动效优先使用透明度和位移，保留现有数字过渡、减少动态效果偏好及固定宽度规则。
- 缓存和队列的具体容量在实现时通过测量确定；释放视图缓存不删除 SQLite 中的历史记录，历史清理仍是单独的数据设置事项。

**性能验收：**

- 使用正式构建测量，记录测试设备、系统和 WebView2 版本；分别测试仅灵动岛空闲常驻、多个会话持续更新、打开较大时间范围的趋势图与日志。
- 统计应用 Rust 核心及其相关 WebView2 进程的总内存，同时观察 CPU、窗口打开耗时和交互流畅度；不能只统计主进程或以安装包大小替代。
- 验证反复打开/关闭主面板、切换平台和时间范围后，没有重复采集或订阅，资源占用能够回落且不持续增长；关闭主面板时灵动岛与采集仍正常。
- 不预先写入未经实测的 MB 承诺。首版建立性能基线后，再确定量化目标与需要优化的瓶颈。

### B.2 额度 / 余额 / 费用（已实现，待真实账号验证）

接口形态参考 sub2api 与 Claude 官方 OAuth 用量端点，均为 **GET 只读**：

| 来源 | 端点 | 凭证 | 能读到 |
|---|---|---|---|
| Claude 官方订阅 | `GET https://api.anthropic.com/api/oauth/usage`，需 `anthropic-beta: oauth-2025-04-20` | OAuth `accessToken`（取自 `.credentials.json` 的 `claudeAiOauth.accessToken`） | `five_hour` / `seven_day` / `seven_day_opus` / `seven_day_sonnet` 各窗口的 `utilization` 与 `resets_at` |
| sub2api 自建网关 | `GET {base}/v1/usage`，`Authorization: Bearer <分组 Key>` | 分组 API Key | `quota{limit,used}`、`rate_limits[]{window,limit,used,reset_at}`、`subscription{daily/weekly/monthly_usage_usd 与对应 limit}`、`balance`、`planName` |

**路由规则**：连接填了「网关地址」就走 sub2api；留空则按平台走官方端点。

**关键约束**：官方 OAuth 用量端点**只认 OAuth token，API Key 会得到 401**。因此 API Key 连接返回「不支持查询」而非「凭证失效」——后者会让用户白跑一趟重新授权。

**五种查询状态**（§2.5）用带标签的联合类型表达，绝不退化成 `Option<f64>`：

| 状态 | 触发 | 界面 |
|---|---|---|
| `ok` | 2xx 且解析成功 | 正常画进度条 / 显示余额 |
| `unsupported` | 该接入方式本就不提供 | 中性灰提示，不是错误 |
| `forbidden` | HTTP 403 | 琥珀「权限不足」 |
| `unauthorized` | HTTP 401 | 红色「凭证失效」，并把连接标记为过期 |
| `rate_limited` | HTTP 429 | 琥珀，附 `Retry-After` 秒数 |
| `failed` | 网络 / 5xx / 解析失败 | 红色，附具体原因 |

刷新失败但有旧值时保留旧值并标注「可能已过期 + 最后更新时间」。余额为 0 显示 `0.00`，查不到才显示「—」。

**费用估算**：`pricing.rs` 按公开价目表（美元/百万 Token，缓存写 1.25×、读 0.1×）推算。
- 价目表未覆盖的模型**不当成 0 元**，其 Token 计入 `uncovered_tokens`，界面明示「未计入」。
- **订阅连接的估算值必须说明口径**：官方订阅按月费计价，估算值是「同等用量走 API 要花多少」，不是实际支出。实测本机近 24 小时折算约 $634，而订阅用户实付月费——这个差距不解释清楚就是误导。

### A.5 实现时容易踩的细节

以下都是设计文件里已经处理、但代码里很容易做错的点。

1. **5h / 7d 标签颜色不随水位变**。标签是「窗口身份色」（5h 淡紫、7d 淡绿），只有**进度条填充**按 75% / 90% 阈值在绿 / 琥珀 / 红之间切换。
2. **所有数字用等宽数字**（`font-variant-numeric: tabular-nums`）。百分比列固定 34px、倒计时列固定 56px 并右对齐——这是 5h 与 7d 两行能对齐的前提，也是刷新时不抖动的前提。
3. **增量区宽度固定**。`+12.4k Token` 出现或消失都不得改变灵动岛宽度、不得推动左侧数据、不得覆盖按钮。空闲时保留 112px 空白。
4. **进度条按百分比精确绘制**。设计文件里每条 bar 的宽度都是 `轨道宽 × 已用比例` 算出来的，不是示意；实现时同理。
5. **失败 ≠ 0% / 满格**。查询失败、未连接、来源不支持时不着色也不画进度条，与「真实已用 0%」和「真实已用 100%」三者必须可区分。
6. **深色不是反色**。`text-secondary` 浅深几乎同色（`#8A8A8A` / `#8E8E8E`），而 `text-tertiary` 浅深差异很大（`#ABABAB` / `#6B6B6B`）——直接反相会毁掉层级。逐项取 A.2 的值。
7. **文字绿和进度条绿是两个值**。进度条用 `success`（`#06C167`），**文字一律用 `success-text`**（`#06834A`）；前者在白底上对比度不足 3:1，做文字会发虚。
8. **应用图标不随主题变化**，深色标题栏里也是白底图标。平台标识则随主题换色（`$logo-*`）。
9. **文本溢出单行截断加「…」**，不换行不缩字号，配 `title` / `aria-label` 给全文；**数值与金额不省略**，宽度不够就加宽列或横向滚动。
10. **日志表窄窗口横向滚动，不隐藏列**。七列宽度之和恒为 1064，宽屏多出的空间只给计费模型列。
11. **趋势图不要用绝对定位对齐标签**。设计文件里 24 根柱与 24 个刻度标签是两个等分的 flex 行，靠布局对齐，不靠手工算位置。
12. **组件实例的主题继承**。设计文件里 `C/*` 组件本身不锁主题，由使用它的画布决定浅深——对应到代码就是组件不得硬编码颜色，一律走 CSS 变量。

### 2026-09-16 运行状态存活校验补充

Codex 日志中的未结束状态不能单独证明执行者仍存在。Windows 运行列表须同时核对该会话的实时独占写入锁；缺失 / 已释放 / 无法确认的锁不计入运行数，不篡改历史记录为已完成。长时间思考、等待输入和压缩期间，只要原写入者仍持有会话，就保留本轮计时与 Token。收到明确结束事件后，即使线程仍被打开也不显示运行。
