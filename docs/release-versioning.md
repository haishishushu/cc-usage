# CC Usage 版本号规则

版本号采用 `主版本.次版本.修订号`。当前版本线从 `0.1.0` 开始，修订号每次加 1；`100` 是这一版本线的最后一个修订号，下一版将次版本加 1，并把修订号归零。

```text
0.1.0 → 0.1.1 → 0.1.2 → … → 0.1.99 → 0.1.100 → 0.2.0 → 0.2.1
```

## 自动构建如何取号

- `main` 分支触发的持续构建，从 `continuous` 发行版已有安装包的文件名读取使用过的版本号，并与 `backend/tauri.conf.json` 的版本号比较，从较高者计算下一版。
- GitHub Actions 的运行次数、取消次数和失败次数不参与版本计算。某次构建即使只上传了部分安装包，该版本也视为已占用，后续构建不会复用它。
- 同一次工作流的 Windows、macOS 和 Linux 安装包共用一个版本号；发布后 `latest.json` 也使用该版本号。
- 如果无法读取现有 `continuous` 发行版，构建停止，避免误用旧版本号覆盖安装包。

`v*` 正式标签仍由维护者创建。创建正式标签时，应按上述顺序设置 `backend/tauri.conf.json` 和 `backend/Cargo.toml`，并让标签名与版本号一致；当前工作流不会自动创建正式标签。
