# 四种连接方式审查与修复

## 结论

Codex Auth 的任务开始、完成、中断、等待和本轮 Token 基础逻辑通过回归检查，但发现运行标记目录未跟随 CODEX_HOME，以及空额度响应被接受的问题，已修正。Claude Auth、Claude API Key、Codex API Key 复用统一的会话展示与按连接能力查询规则。

## 改动总结

- Claude 从最近 90 秒有记录改为明确的轮次生命周期：用户消息开始，工具执行、等待和压缩维持本轮，end_turn、turn_duration 或用户中断结束；元数据和侧链不会启动主会话。进程/注册标记过滤负责关闭客户端后的清理。
- 两个平台共享本轮起点、Token 增量和运行会话查询。旧 Claude 扫描检查点首次安全重建，去重后不重复累计 Token。
- 查询只跟随显式启用的连接。Auth 查询订阅额度；官方 API Key 查询组织统计；兼容网关查询额度和钱包。未选择和暂停不会自动借用本机 Auth。切换连接时隐藏上个连接的数据。
- 普通 API Key 用无模型调用费用的模型列表验证。组织接口 401 时再次确认模型访问，避免把缺少 Admin 权限误报为凭证过期；403 不作为凭证有效的证据。连接状态变化广播给界面，迟到查询不能恢复已暂停连接。
- 官方域名的 /v1 基址归一化，不再误路由到网关；Auth 不向自定义网关发送凭证。
- 本机估算费用随 live-usage / refresh-requested 更新查询截止时间，组织费用、组织 Token 和本机估算明确区分。缺字段、无效金额、未完整分页的响应不能显示成零。真实零值保留为零。

## 验证边界

没有用鼠鼠的真实凭证逐一验证四种官方账号，不宣称服务端权限、额度窗口和账单接口对所有账号都可用。组织统计要求相应 Admin 权限，普通 Key 回退到本机统计；官方订阅不提供钱包余额。本地日志按平台统计，不能归属到具体账号或 Key。日志缺少可靠结束事件且运行标记不可读取时，仍只能保守保留状态；不能凭时间短暂沉默认定已结束。

组织接口若仍返回分页，将显示数据不完整而不会把部分响应冒充总量；当前查询按今日范围请求最多 31 个日桶。
