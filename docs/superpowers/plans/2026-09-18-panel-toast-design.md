# 主面板 Toast 反馈体系设计（2026-09-18）

参考 [cc-switch](https://github.com/farion1231/cc-switch) 的反馈观感（`position="top-center"`、成功 2000ms / 失败 4200ms 自动消失），但**不引入 `sonner` 依赖**，改为自研轻量实现，以复用本项目既有的设计变量与动效体系。

已由用户确认的三项选择：

1. **覆盖范围**：全量覆盖主面板写操作，并把「一次性结果」类的就地文字提示迁入 Toast；「持续状态」类提示留在原地。
2. **技术选型**：自研，纯逻辑进 `lib/` 配 `node --test` 单测，零新增依赖。
3. **位置形态**：工具栏下方、顶部居中，向下堆叠，最多 3 条。

## 1. 模块划分

| 文件 | 职责 |
| --- | --- |
| `src/lib/toastQueue.ts` | 纯函数：入队去重、条数上限、退场标记、剩余时长计算、暂停后平移 |
| `src/lib/toastQueue.test.mjs` | `node --test` 单测，覆盖上述全部纯函数 |
| `src/components/ui/Toast.tsx` | `ToastProvider` / `ToastViewport` / `useToast()` |
| `src/index.css` | `.motion-toast` 进出场过渡 |

对外接口只有一个 hook：

```ts
const toast = useToast()
toast.success("已切换到 kjqy-claude", "灵动岛改为显示该连接")
toast.danger("更换 API Key 失败", String(reason))
```

`ToastProvider` 拆成两个 context：`ToastApiContext`（值稳定，供调用方）与 `ToastStateContext`（值随队列变化，只供视口）。调用方因此不会被队列变化牵连重渲染。

无 Provider 时 `useToast()` 返回一组空操作而非抛错——`SettingsView` 也会在浏览器预览的 Showcase 里被渲染，不能因为缺 Provider 就崩。

## 2. 队列规则

- **上限 3 条**：新条目入队后，若未退场的条目超过 3，最旧的一条被标记退场（保留 140ms 退场动画，而非瞬间消失）。
- **同内容不堆叠**：tone + 标题 + 详情完全相同且尚未退场时，不新增条目，只重置该条计时。连点「更新」不会刷屏。
- **悬停暂停**：鼠标悬停或键盘聚焦视口时暂停全部倒计时，移开后把 `createdAt` 统一平移已暂停的时长继续计时。报错文案要留得住读完的时间。
- **停留时长**：

  | tone | 语义 | 时长 |
  | --- | --- | --- |
  | `success` | 操作成功 | 2200ms |
  | `info` | 无变化的正常结果（如「已是最新」） | 2200ms |
  | `warn` | 操作未达成但非错误（如「未找到本机配置」） | 3600ms |
  | `danger` | 失败 | 4800ms |

## 3. 视觉与层级

```
┌──────────────────────────────────────────────────┐
│ ◉ CC Usage                  ─   □    ✕   │ TitleBar h-10 (40px)
├──────────────────────────────────────────────────┤
│ [总览│设置]                        [平台 ▾]      │ Toolbar  h-14 (56px)
├──────────────────────────────────────────────────┤
│              ╭────────────────────────────╮      │ ← top 96px + 12px
│              │ ✔ 已切换到 kjqy-claude   ✕ │      │
│              ╰────────────────────────────╯      │
│              ╭────────────────────────────╮      │
│              │ ⚠ 未在本机找到该连接的配置 │      │
│              ╰────────────────────────────╯      │
│   内容区                                          │
└──────────────────────────────────────────────────┘
```

- 配色直接取既有变量：`--success-soft/--success-text`、`--accent-blue-soft/--accent-blue`、`--warn-soft/--warn`、`--danger-soft/--danger`，深浅色自动跟随，无需额外桥接。
- 视口用 `absolute inset-x-0 top-[96px] z-[60]`，容器 `pointer-events-none`、条目 `pointer-events-auto`。
  - 用 `absolute` 而非 `fixed`：主面板在 Tauri 真窗口是铺满的，在浏览器预览里是带外边距的卡片，绝对定位在面板根节点内两种模式都落位正确。
  - `z-[60]` 高于连接对话框的 `fixed inset-0 z-50`：「换 Key 失败」必须能盖在对话框之上。
- 动效复用既有体系：进场 `@starting-style`，退场 `data-state="closed"` 后 140ms 卸载，与 `.motion-dialog`、`useExitPresence` 同节奏；`prefers-reduced-motion` 由 `index.css` 既有全局兜底接管。
- 无障碍：视口 `aria-live="polite"`；`danger` 条目单独 `role="alert"`。

## 4. 调用点覆盖

| 位置 | 交互 | Toast | 就地提示的处理 |
| --- | --- | --- | --- |
| 连接管理 | 更新凭证 | 已更新 / 已是最新 / 未找到 / 不匹配 / 失败 | 按钮只保留「更新 / 更新中」，结果文案迁出 |
| 连接管理 | 启用 / 断开 / 重新连接 | 已切换到 xxx / 已断开 xxx / 已重新连接 | 行内红字迁出 |
| 连接管理 | 移除（确认后） | 已移除 xxx，历史统计保留 | 对话框内校验红字保留 |
| 连接管理 | 重命名 / 更换 API Key | 已重命名为 xxx / 已更换 API Key | 对话框内红字保留 |
| 连接管理 | 添加连接 | 已添加 N 个 xxx 连接 | 向导内分步红字保留 |
| 常规 | 开机自启开关 | 已开启 / 已关闭 / 失败 | `autostartError` 迁出 |
| 数据 | 打开数据文件夹 | 仅失败弹 | `dataError` 迁出 |
| 数据 | 导入 / 导出 | 成功带数量或路径，失败带原因 | `dataAction` 迁出 |
| 数据 | 历史清理 | 已清理 N 条请求记录 / 预览失败 / 清理失败 | 黄色确认条保留 |
| 代理 | 启停 / 改端口 | 已启动 127.0.0.1:port / 已停止 / 失败 | `last_error` 就地保留 |
| 套餐凭证 | 保存 | 已保存 / 保存失败 | `message` 迁出 |
| 总览 | 重试采集 / 重试查询 | **仅失败弹** | 加载骨架与状态区保留 |

**迁移判据**：一次性的操作结果进 Toast；会持续存在的状态留在原地（连接列表加载失败重试条、`cfg.error` 顶部红条并带「重新读取」、代理最近转发错误、历史清理确认条）。

## 5. 刻意不弹的三处

覆盖范围虽是「全量」，以下三处**只在失败时弹**，成功不弹，理由是结果本身当场可见，再弹一条属于重复播报：

1. 主题切换（浅色 / 深色 / 跟随系统）——整个界面当场变色。
2. 平台切换、灵动岛显示平台与显示模式——选中态与数据立刻变化。
3. 历史保留天数下拉——下拉框显示的就是新值。

## 6. 验证

- `cd frontend && node --test "src/lib/*.test.mjs"`：新增 `toastQueue` 用例与既有用例一起跑通。
- `pnpm --dir frontend build`（含 `tsc -b`）：改动横跨 8 个文件，类型必须全量过。
- 实机跑 Tauri：连点「更新」验证不刷屏；在换 Key 对话框内制造失败，验证 Toast 盖得住 `z-50` 对话框。
