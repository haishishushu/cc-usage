# 八个平台完整接入设计

## 目标与范围

鼠鼠已确认：Claude、Codex、Gemini、Grok、Zcode、Trae、Qoder、Workbuddy 均覆盖连接管理、用量与缓存统计、额度／余额、会话及灵动岛；各项以平台真实提供的数据为准。

完成标准不是开放八个标签，而是每项操作有真实后端路径、明确结果和相应验证。来源缺失、接口不支持、登录过期、权限不足、网络故障分别表达；不将这些状态伪装成成功或零用量。

保留当前视觉布局。未获授权不提交、切换分支或重置 Git。不因实现适配而自动更换用户实际使用的模型、渠道或账号。

## 已核实的现状

| 平台 | 仓库实现与本机证据 | 缺口 |
| --- | --- | --- |
| Claude | 已有连接、会话采集、额度与余额、统计、灵动岛；缓存读取 `message.usage` | 复核连接切换、状态一致性、未知字段与零值，保留现有工作链路 |
| Codex | 已有连接、会话采集、额度与余额、统计、灵动岛 | 同上；保持输入已含缓存的独立口径 |
| Gemini | 前端 `not-integrated`，连接白名单未支持；本机 `.gemini` 有配置，但未发现 CLI 会话目录 | 新增经官方格式验证的连接与会话适配，不能把 Antigravity 目录当成 Gemini CLI 会话 |
| Grok | 存在本机 OAuth 额度查询模块；前端仅声明额度能力 | 没有完整连接管理和会话采集；现有 protobuf 启发式解析需要单独验证 |
| Zcode | 凭证读取仅猜测 `.zcode` 根目录；本机实际发现 `.zcode/v2/credentials.json` 与 `tasks-index.sqlite` | 真实凭证格式、任务关联、用量来源和额度认证尚未接通 |
| Trae | 前端标识 `trae`，后端新增白名单却写成 `tare` | 标识错误；真实登录、会话及额度格式待核实；本次初查未找到本机安装数据 |
| Qoder | 本机 `.qoder`、`.qoder-cn` 有项目 JSONL；桌面端数据另在 Roaming 目录 | 现有根目录 token 猜测不适用；国内版样本有 `message.usage.credits`，部分 Token 为 0；国际版已查看样本未含 usage |
| Workbuddy | 本机 `.workbuddy` 与 `.workbuddy-ai` 都有 `workbuddy.db`；存在 `sessions` 与 `session_usage` | 现有 token 猜测不适用；需辨明 `used`、`size`、`credit_json` 的真实单位及累计语义 |

具体共享缺陷：

- `frontend/src/lib/platforms.ts` 的可用声明与后端实际能力不一致。
- `backend/src/creds.rs` 用通用文件名及字段猜测四个平台的凭证，无法证明读到的是正确的登录凭证。
- `backend/src/cli_apply.rs` 只实现 Claude／Codex，但其他平台的启用操作仍可能进入该路径。
- `backend/src/quota.rs::validate_connection` 主要支持 Claude／Codex，不能支撑八个平台的统一“检测成功”。
- `backend/src/db.rs` 导入平台白名单只有 Claude／Codex／Gemini／Grok，需要与实际平台能力保持一致。
- 当前请求记录不关联连接 ID，无法可靠按账号拆分本地历史；不得由当前选中连接反推旧记录归属。

## 方案选择

采用“逐平台适配、统一数据与界面”的方案。

不采用把所有平台套到 OpenAI／Anthropic 协议的方式：桌面产品的会话、凭证、积分结构已经存在明显差异。

不采用复制八套页面的方式：连接状态、空值展示、查询周期与错误处理应共用，避免修一处遗漏其他平台。

## 前后端职责

### 平台能力

后端维护明确的平台能力描述，前端读取并据此控制操作与展示。能力包含：本机连接发现、手动 API 连接、远程凭证验证、外部配置切换、会话采集、Token 分项、积分、额度、余额、实时状态、成本估算。

每项能力区分已支持、来源未配置、来源暂不可用、尚未实现。连接凭证存在只证明已读取，不能自动表示远程验证成功。

真实接口或本地格式未经验证时，不声明已支持。实现完成报告必须列出仍缺样本或平台权限的项目。

### 连接生命周期

统一提供：发现／添加、去重、检测、编辑、启用、暂停查询、移除。

- 去重依据平台、来源实例、账号或凭证身份；国内版和国际版不能误合并。
- 检测返回检测范围：本地读取检查或远程认证验证，以及时间与错误原因。
- API 配置与 OAuth 会话分开处理；不得只替换 access token 后保留另一个账号的 refresh token。
- “用于本应用监控”和“切换外部工具账号／模型”是两种操作；外部切换只在有可靠平台实现时开放。
- 断开或暂停不删除历史数据；移除连接不冒充已退出外部客户端。
- 保存失败、外部配置写入失败或验证失败时不得提前显示启用成功。
- 配置写入先备份，原子替换，保留无关配置；发生部分失败需恢复或明确报告失败阶段。
- 凭证仅发往该凭证所属平台或用户明确配置的地址，不输出到日志、测试报告或通知中。

### 会话与用量采集

各适配器输出统一的来源、平台、实例、会话 ID、请求 ID、时间、模型与可选用量字段。Token、积分、金额分别存储，保留单位及来源，不能互相冒充。

- Claude／Codex 保持现有来源，补针对性回归。
- Gemini 按官方会话格式分别处理 JSON 快照和 JSONL 追加记录；同消息更新按 ID 更新而非重复累加。
- Qoder 区分 `.qoder` 与 `.qoder-cn`，处理 usage 存在／缺失、积分及同消息更新。
- Zcode 先核对任务索引与真实记录关联，再实现适配；索引中的任务数量不是请求量。
- Workbuddy 只读访问原生 SQLite，辨明会话累计量与上下文占用，后者不能累计成总消耗。
- Grok／Trae 按官方资料或真实样本确定来源，禁止以其他平台格式猜测解析。
- 日志追加、文件重写、未完成尾行、重启续扫、重复事件与多个来源同时出现必须保持幂等。
- SQLite 来源采用短只读查询和游标；应用不得迁移或修改第三方数据库。
- 运行／等待／结束／失败由明确事件或已验证状态映射，不仅凭文件刚更新就判定正在生成。

### 缓存与统计口径

缓存创建、缓存命中分别保留来源数值；缺失为未知，报告为 0 则保留 0。不能由未命中量、下一次命中量或积分反推缓存创建。

输入是否包含缓存由每个平台的已核实格式决定。不能继续仅以“是否 Codex”二分所有平台。来源提供真实总量则优先采用；未提供时仅在字段语义完整时计算。

区间内混有缺失字段时，不将部分已知合计标成完整合计。缓存命中率必须建立在已知且可比较的分母上。成本只对有验证过的模型价目及计价字段估算，并明确标注估算。

### 额度、余额与刷新

平台适配器返回窗口、重置时间、单位、账户范围与查询状态；无公开或可验证接口时显示具体限制，不填默认额度。

刷新支持去重、超时、退避及凭证变更后缓存失效。失败时可展示带时间的旧数据；不得把旧额度冒充刚同步的结果。切换平台／连接后的过期响应不能覆盖当前页面。

### 界面与灵动岛

沿用八个平台标签及现有表格。每个平台的按钮由后端能力驱动；无数据、未登录、不支持、读取失败分别呈现。桌面真实路径不回退到 mock 演示值。

灵动岛及托盘复用同一来源与快照：有 Token 展示 Token，有积分展示积分，有额度展示额度；字段缺失不显示虚假百分比。页面保留来源范围说明。

## 验收

每个平台都记录：格式依据、脱敏样本、解析验证、后端操作验证、前端状态验证、是否完成本机真实验证。

共享回归覆盖：

1. 八个平台标识、能力与前后端命令一致。
2. 连接去重、检测失败、编辑、暂停、移除及启用失败不会产生虚假成功状态。
3. 缺失与 0、缓存输入口径、累计与增量、积分与 Token 不混淆。
4. 文件重扫及应用重启不重复计数；单平台失败不阻断其他平台。
5. 统计、趋势、日志、会话、灵动岛使用一致来源；刷新竞态不串平台。
6. 配置写入与回滚使用隔离临时目录测试，不覆盖用户真实登录配置。
7. 前后端构建、相关单元与集成测试通过，再用隔离应用执行交互验收。

缺少真实样本的平台可以完成适配框架和基于官方格式的测试，但必须标为“未完成真实环境验证”，不能据此宣称八个平台均已实测通过。

## 实施顺序

1. 统一平台能力、连接状态和输入校验，修复 `trae` 标识错误及失配入口。
2. 逐平台实现真实来源适配；优先已有本机证据的 Zcode、Qoder、Workbuddy，以及有官方格式的 Gemini。
3. 补齐 Grok、Trae 的已验证接口与来源；需要实际登录或样本时集中列出缺项。
4. 接入统一采集、数据库、额度刷新和错误状态。
5. 完成统计页面、会话、灵动岛与托盘联动。
6. 隔离验证、真实来源只读验收，输出逐平台结果与剩余限制。
